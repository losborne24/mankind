# Elevation data provenance

The globe's **stylised terrain relief** (Phase 2) is derived from real
elevation: a bounded, low-zoom pyramid of **Terrarium-encoded DEM tiles**,
self-hosted as the PNG files in this directory and served as static assets from
the application's own origin.

These tiles are generated by [`scripts/fetch-dem.mjs`](../../../scripts/fetch-dem.mjs).
They are committed so that `pnpm install` and `pnpm build` never need network
access. Re-run the script only to refresh the data.

## What is bundled

| Path                         | Content                                  | Extent  |
| ---------------------------- | ---------------------------------------- | ------- |
| `public/geo/dem/{z}/{x}/{y}.png` | Terrarium RGB elevation tiles (256 px) | z0 – z4 |

- **341 tiles, ~12 MB total** — the full `z0…z4` quadtree pyramid (1 + 4 + 16 +
  64 + 256 tiles). Only the tiles inside the current viewport are ever
  downloaded by the browser.
- **Terrarium encoding:** `elevation(m) = (R * 256 + G + B / 256) − 32768`.
  MapLibre reads this directly via `encoding: "terrarium"` on the `raster-dem`
  source (see [`map/terrain.ts`](../../../map/terrain.ts)).
- **Ocean is clamped to sea level.** The raw tiles carry bathymetry (negative
  depths). The fetch script clamps every below-sea-level pixel to exactly 0 m
  (Terrarium RGB `128,0,0`) so that, under 3D terrain, oceans are a **flat
  plane** and the land rises cleanly out of the water instead of the sea floor
  sinking below the coast and cutting a cliff at every shoreline (which draped
  layers — the coastline stroke especially — would trace as vertical walls).
  Land elevation is untouched. Clamping also happens to shrink the bundle
  (flat ocean compresses well), roughly halving it.
- **Deliberately coarse.** The native maximum is z4 (≈4 km/px near the equator);
  MapLibre **overzooms** past it for closer views. That coarseness, smoothed by
  overzoom, is exactly what gives the hillshade its soft, painterly, non-noisy
  character — it is a stylistic choice, not a fidelity ceiling. Bumping the
  `MAX_ZOOM` in the fetch script trades repo weight (~4× per level) for sharper
  mountains at regional zoom.

## Source (open data)

- **Dataset:** the AWS **Terrain Tiles** open dataset —
  <https://registry.opendata.aws/terrain-tiles/> — distributed as Terrarium PNG
  tiles at `s3://elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`.
- **Underlying elevation** is a public composite of national and global DEMs:
  **SRTM**, **GMTED2010**, **ETOPO1** (bathymetry/high latitudes), and other
  public-domain national sources. See the dataset's attribution page for the full
  per-source list.

## License, attribution & redistribution

- The Terrain Tiles dataset is published as **open data** for any use; the
  underlying sources above are **public domain / openly licensed** and carry no
  per-request or paid dependency, so the tiles are safe to commit and ship.
- We credit the dataset by courtesy in the on-globe attribution control (see
  `DEM_ATTRIBUTION` in [`map/terrain.ts`](../../../map/terrain.ts)). If you bump
  the resolution or re-host, keep that attribution and check the current
  attribution guidance on the dataset page above.

## Cost, hosting & bandwidth

- **No paid service and no third-party runtime dependency.** Tiles are served
  from our own static origin — no API key, rate limit, usage quota, or
  per-request cost, and no external endpoint that can throttle or disappear
  (the same stance as the Natural Earth land in [`../PROVENANCE.md`](../PROVENANCE.md)).
- **Transfer is bounded and viewport-driven.** MapLibre requests only the DEM
  tiles covering the current view; a user never downloads the whole pyramid.
- **Serve with HTTP compression off for these PNGs** — Terrarium tiles are
  already PNG-compressed noise-like data and do not benefit from gzip/brotli; the
  committed byte size is the transfer size.

## How it becomes the look

Two MapLibre layers turn this elevation into the stylised terrain, both defined
in [`map/terrain.ts`](../../../map/terrain.ts):

1. **`color-relief`** — a near-grayscale *value* ramp keyed to elevation (tonal
   lowland/upland/mountain separation; **not** biome colour), transparent at and
   below sea level.
2. **`hillshade`** — a soft, single warm key light (`igor` method, low
   exaggeration) for the sculptural form.

A second, inverse `color-relief` **"sea cover"** repaints clean ocean over the
DEM's submarine (bathymetry) relief. The relief is composited **above the opaque
Natural Earth land fill and below the crisp coastline stroke**, so the
authoritative land shape and coast always come from the vector data and the
coarse DEM's own coastline never has to agree with it.
